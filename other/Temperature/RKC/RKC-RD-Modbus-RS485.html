Hướng Dẫn Truyền Thông RS-485 Modbus RTU & Bảng Thanh Ghi (Register Map) Đồng Hồ Nhiệt RKC

Trong các hệ thống tự động hóa công nghiệp, việc kết nối đồng hồ điều khiển nhiệt độ RKC (RD Series: RD100, RD400, RD500, RD700, RD900 & RB/REX Series) với PLC, màn hình HMI hay máy tính SCADA qua chuẩn giao tiếp RS-485 Modbus RTU là giải pháp phổ biến giúp giám sát và điều khiển tập trung.

Bài viết này cung cấp hướng dẫn chi tiết về cấu hình phần cứng, nguyên lý đấu nối bus RS-485, bảng tra cứu địa chỉ thanh ghi Modbus (Register Map / Register Code) đầy đủ và ví dụ khung truyền thông thực tế.

1. Tổng Quan Về Chuẩn Truyền Thông RS-485 Modbus RTU​

1.1. Thông Số Truyền Thông Tiêu Chuẩn​

Đồng hồ nhiệt RKC hỗ trợ 2 chuẩn giao thức truyền thông nối tiếp chính qua cổng RS-485:

  1. Giao thức RKC ANSI Communication (Giao thức riêng biệt của RKC).
  2. Giao thức Modbus RTU (Chuẩn công nghiệp phổ biến nhất).

Để truyền thông với PLC (Siemens, Mitsubishi, Omron, Delta, Schneider...) hoặc HMI/SCADA, cần chuyển giao thức trong cài đặt đồng hồ sang Modbus RTU.

2. Sơ Đồ Đấu Nối Chuẩn Bus RS-485 (Multidrop Topology)​

2.1. Sơ Đồ Kết Nối Chân Chống Nhiễu​

Truyền thông RS-485 sử dụng tín hiệu vi sai 2 dây A(+)A (+)A(+) và B(−)B (-)B(−). Đối với dòng đồng hồ RKC RD400 (24 chân):

  • Chân 14: Tín hiệu A(+)A (+)A(+) hay còn gọi là T/R(A) hoặc D+.
  • Chân 15: Tín hiệu B(−)B (-)B(−) hay còn gọi là T/R(B) hoặc D-.
  • Chân 13: Chân mát tín hiệu SG (Signal Ground / Shield Line).
   PLC / HMI Master                  RKC Slave 1 (ID: 1)              RKC Slave 2 (ID: 2)              RKC Slave N (ID: N)
  +------------------+              +-------------------+            +-------------------+            +-------------------+
  |  RS-485 Port     |              |  RKC RD400        |            |  RKC RD400        |            |  RKC RD400        |
  |  Terminal A (+)  |------------->|  Chân 14: A (+)   |----------->|  Chân 14: A (+)   |----------->|  Chân 14: A (+)   |---+
  |                  |              |                   |            |                   |            |                   |   | [120 Ohm]
  |  Terminal B (-)  |------------->|  Chân 15: B (-)   |----------->|  Chân 15: B (-)   |----------->|  Chân 15: B (-)   |---+
  |                  |              |                   |            |                   |            |                   |
  |  Shield / SG     |=============>|  Chân 13: SG      |===========>|  Chân 13: SG      |===========>|  Chân 13: SG      |
  +------------------+              +-------------------+            +-------------------+            +-------------------+

2.2. Quy Tắc Kỹ Thuật Đấu Nối Cần Tuân Thủ​

  1. Topolgy nối tiếp (Daisy-chain): Kết nối dây từ thiết bị này sang thiết bị tiếp theo. Không đấu nối dạng hình sao (Star Topology) hoặc nhánh rẽ dài (T-branch) để tránh phản xạ tín hiệu trên đường truyền.
  2. Điện trở cuối đường dây (Termination Resistor): Đấu nối 1 điện trở 120 Ω−1/4W120\text{ }\Omega - 1/4\text{W}120 Ω−1/4W song song giữa chân AAA (14) và BBB (15) chỉ tại thiết bị đầu tiên và thiết bị cuối cùng trên bus truyền thông.
  3. Cáp chống nhiễu: Sử dụng cáp xoắn đôi có lớp lưới bọc chống nhiễu (Twisted Pair Shielded Cable). Lớp lưới chống nhiễu đấu nối vào chân SG (chân 13) và nối đất 1 đầu duy nhất tại tủ điện.

3. Bảng Tra Cứu Thanh Ghi Modbus (Modbus Register Map)​

Đồng hồ RKC sử dụng bảng thanh ghi Holding Registers (4X). Các mã lệnh Modbus chuẩn được hỗ trợ:

  • Function Code 03H: Đọc một hoặc nhiều thanh ghi (Read Holding Registers).
  • Function Code 06H: Ghi một thanh ghi đơn (Write Single Register).
  • Function Code 10H (16 Decimal): Ghi nhiều thanh ghi liên tiếp (Write Multiple Registers).

:::info Quy tắc dữ liệu & Dấu chấm động

  • Dữ liệu số đo nhiệt độ (PVPVPV, SVSVSV, EVEVEV) trong thanh ghi Modbus được lưu dưới dạng số nguyên 16-bit có dấu (Signed 16-bit Integer).
  • Khi cài đặt độ phân giải số thập phân 0.1∘C0.1^\circ\text{C}0.1∘C (mã F01 = 1), giá trị đọc về từ thanh ghi bằng Giá trị thực ×10\times 10×10. (Ví dụ: Nhiệt độ thực 150.5∘C150.5^\circ\text{C}150.5∘C sẽ lưu trong thanh ghi là 150515051505). :::

4. Phân Phích Khung Truyền Modbus RTU Thực Tế​

4.1. Ví Dụ 1: Đọc Nhiệt Độ Thực Tế (PVPVPV) Từ Đồng Hồ Slave ID = 1 (Function Code 03H)​

Giả sử cần đọc thanh ghi PV (Địa chỉ Hex 0000H) từ đồng hồ nhiệt có địa chỉ Modbus là 1:

Khung Yêu Cầu (Master Request):

[Address] [Func] [Start Addr High] [Start Addr Low] [Count High] [Count Low] [CRC Low] [CRC High]
  01        03         00               00             00           01         84        0A

Khung Phản Hồi (Slave Response):

[Address] [Func] [Byte Count] [Data High] [Data Low] [CRC Low] [CRC High]
  01        03        02          05          E8         B8        FA
  • Dữ liệu nhận về: 05E8H (Thập phân = 1500).
  • Nếu cài đặt dải số thập phân 0.1∘C0.1^\circ\text{C}0.1∘C, giá trị nhiệt độ đo thực tế PV=150.0∘CPV = 150.0^\circ\text{C}PV=150.0∘C.

4.2. Ví Dụ 2: Ghi Nhiệt Độ Cài Đặt Mục Tiêu SV1=200.0∘CSV1 = 200.0^\circ\text{C}SV1=200.0∘C (Function Code 06H)​

Muốn cài đặt giá trị nhiệt độ mục tiêu SV1=200.0∘CSV1 = 200.0^\circ\text{C}SV1=200.0∘C (Giá trị số nguyên ghi vào Modbus = 2000=07D0H2000 = \text{07D0H}2000=07D0H) vào thanh ghi 0006H của đồng hồ Slave ID = 1:

Khung Phản Hồi Xạc Nhận (Slave Response):

  01        06         00              06           07          D0         6B        0D

5. Ví Dụ Lập Trình Đọc/Ghi Modbus RS-485 Bằng Python​

Dưới đây là đoạn mã Python minh họa sử dụng thư viện pymodbus hoặc minimalmodbus để đọc nhiệt độ thực tế PVPVPV và cài đặt nhiệt độ SV1SV1SV1 qua bộ chuyển đổi USB-to-RS485:

import minimalmodbus

# Khởi tạo thiết bị kết nối cổng COM qua RS-485
# Thay 'COM3' (Windows) hoặc '/dev/ttyUSB0' (Linux) theo cấu hình thực tế
controller = minimalmodbus.Instrument(port='COM3', slaveaddress=1)

# Cấu hình thông số truyền thông RS-485
controller.serial.baudrate = 9600      # Tốc độ Baud Rate 9600 bps
controller.serial.bytesize = 8         # 8 Data Bits
controller.serial.parity   = 'N'       # Parity None
controller.serial.stopbits = 1         # 1 Stop Bit
controller.serial.timeout  = 0.5       # Timeout 500ms
controller.mode = minimalmodbus.MODE_RTU

try:
    # 1. Đọc giá trị nhiệt độ thực tế PV (Thanh ghi 0x0000 = 0 Decimal)
    # number_of_decimals=1 để tự động chia 10 lấy số thập phân (Ví dụ 1500 -> 150.0 °C)
    pv_temperature = controller.read_register(registeraddress=0, number_of_decimals=1, functioncode=3)
    print(f"Nhiệt độ đo thực tế (PV): {pv_temperature} °C")

    # 2. Đọc giá trị nhiệt độ cài đặt SV1 (Thanh ghi 0x0006 = 6 Decimal)
    sv_temperature = controller.read_register(registeraddress=6, number_of_decimals=1, functioncode=3)
    print(f"Nhiệt độ cài đặt mục tiêu (SV1): {sv_temperature} °C")

    # 3. Ghi giá trị SV1 mới = 180.0 °C vào thanh ghi 0x0006
    new_sv = 180.0
    controller.write_register(registeraddress=6, value=new_sv, number_of_decimals=1, functioncode=6)
    print(f"Đã cập nhật cài đặt SV1 thành công: {new_sv} °C")

except Exception as e:
    print(f"Lỗi giao tiếp truyền thông RS-485 Modbus: {e}")
